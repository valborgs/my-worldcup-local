# 일본어 표시 검증

검증일: 2026-09-16. 브랜치: `codex/issue-29-localization-setup`.

## 구현

- `app_ja.arb`에 한국어 원본과 동일한 324개 키를 제공한다.
- 한국어가 기본/fallback이며, 일본어 시스템 설정에서는 일본어를 선택한다.
- 온보딩, 화면/버튼, 입력 검증, 오류/전송 상태, 기본 샘플 이름,
  공유 문구, 접근성 안내, 앱 이름과 iOS 권한 안내를 포함한다.
- 실제 기기 접근성 트리에서 발견한 온보딩의 `Page 1 of 5`는
  `progressSemantic`과 새 `onboardingProgress` 리소스로 수정했다.

## Android 에뮬레이터

실행 중인 `emulator-5554`의 Android 설정에서 일본어를 추가하고 첫 언어로
이동했다. `settings get system system_locales` 결과는 `ja-JP,en-US`였다.
Android 17 / API 37, `sdk_gphone16k_x86_64`에서 디버그 APK를 설치해 실행했다.
2076×2152 화면과 임시 1080×1920 화면에서 확인했다.

| 경로 | 확인한 내용 |
| --- | --- |

검증용 문의는 실제 서버에 전송하지 않았다. 공유 창에서 외부 앱/상대에게
파일을 보내지 않았다. 검증용으로 가져온 월드컵은 확인 후 삭제했다.

## 자동 검증

- `flutter analyze --no-pub`: 오류 없음.
- 포맷 검사와 `git diff --check`: 통과.
- Flutter 및 Android/iOS 리소스 재생성 결과: 변경 없음.
- `flutter build apk --debug --no-pub`: 성공, 수정된 APK 재설치 후 온보딩 재확인.
- 앱 및 테스트가 있는 모든 패키지: **267개 테스트 통과**.
- 일본어 ARB 키 누락/빈 값/한국어 잔류/placeholder 변경을 검사한다.
- 한국어·일본어 기기 선택과 미지원 언어의 한국어 fallback을 검사한다.
- 열린 온보딩의 한국어→일본어 전환과 페이지 안내 갱신을 검사한다.
- 모든 `AppMessageId`의 일본어 매핑, 기본 샘플의 전체 후보 매핑을 검사한다.
- 모의 API로 일본어 문의 검증·접수 결과·서버 콘텐츠 보존·공지 날짜를 검사한다.
- 모의 전송 이벤트로 기기 이름과 인증 코드/수락/거절 UI를 검사한다.
- 작은 화면과 큰 글자에서 일본어 필수 업데이트 안내를 검사한다.

## 범위와 확인 한계

이미지 속 글자와 합의된 제외 항목(디버그 시드 데이터, 로그/진단 문자열,
사용자·서버 콘텐츠)은 원문을 유지한다. 검색 목록에서 한국어 디버그 시드가
보이는 것은 이 제외 범위에 해당한다.

외부 테스트 광고에는 영어 본문과 `OPEN`, 광고 닫기의 `Close` 접근성 문구가
실제로 남아 있었다. 이들은 광고 SDK/공급자가 관리하며 앱 ARB로 번역할 수 없다.
따라서 화면에 들어오는 외부 콘텐츠까지 모두 일본어라고 주장하지 않는다.

모든 오류 분기와 전송 완료 상태를 실제 기기로 유발한 것은 아니다.
실기기 간 전송/카카오 전송/문의 접수, Play 배포가 필요한 업데이트 흐름은
이번 에뮬레이터 검증에서 실행하지 않았으며 관련 앱 문구는 자동 테스트로 보완했다.
iOS는 일본어 리소스와 Xcode 등록까지만 완료했고 Windows 환경에서 실행하지 않았다.

기본 샘플은 표시 시 번역하며 저장된 한국어 원본은 유지한다.
검색은 아직 저장된 원문을 기준으로 하므로 일본어로 번역된 샘플 제목 검색은
별도 기능 보완이 필요하다.
